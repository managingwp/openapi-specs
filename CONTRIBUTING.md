# Contributing

## What belongs here

An API belongs in this repository when it meets one of these tests:

- it has no public OpenAPI document, and the vendor publishes enough API
  documentation to write one; or
- it has an OpenAPI or Swagger document that does not load cleanly into
  MCPHub or another OpenAPI-to-MCP bridge.

This is not a mirror. `APIs.guru` already mirrors the public directory; the value
here is a spec that has been fixed and tested for MCP use.

## Layout

```
specs/<api>/openapi.json            cleaned, MCP-ready OpenAPI 3.0.3
specs/<api>/openapi.readonly.json   generated GET-only variant
specs/<api>/mcphub.json             MCPHub server config with a placeholder token
specs/<api>/source.md               provenance, changes, test status, terms
tools/lib/                          shared fix-ups
tools/convert_<api>.py              per-API converter
tools/lint_mcp.py                   MCP constraint linter
tools/make_readonly.py              read-only generator
```

`openapi.json` is generated by the converter and must be reproducible. Never
hand-edit it; change the converter instead. `openapi.readonly.json` is generated
from `openapi.json` by `tools/make_readonly.py` and is never hand-edited.

## Add an API

1. **Check the terms.** Read the vendor's API documentation and terms. Do not add
   an API whose terms forbid redistributing its documentation. Record what you
   checked in `source.md`.
2. **Write the converter.** Create `tools/convert_<api>.py` on top of
   `tools/lib/`. Fetch the source document (or accept `--source` for a local
   copy) and write to `specs/<api>/`.
3. **Set a real server.** Pass an explicit production `server_url`; never ship
   `localhost`, `127.0.0.1` or a placeholder host.
4. **Declare authentication.** Add an `apiKey`, `bearer` or `basic` scheme even
   when the vendor's document has none. Use a documented placeholder in every
   example.
5. **Name the tools.** Supply an operationId mapping for every operation.
   Unmapped operations fall back to a generated snake_case name. Names must be
   unique, at most 40 characters, and only `[a-z0-9_]`.
6. **Repair bracketed names.** Query parameters such as `q[start_date]` become a
   single `q` object with `style: deepObject` and `explode: true`. Form fields
   such as `domain[address]` become nested JSON body properties. Record in
   `source.md` that deepObject support depends on the bridge and whether it was
   tested.
7. **Fix types and prose.** Run the shared type fixes, convert HTML descriptions
   to Markdown, re-split flattened lists, strip example credentials, and add a
   generic JSON success response plus the shared `Error` response.
8. **Generate the outputs.**

   ```sh
   python tools/convert_<api>.py
   python tools/make_readonly.py
   python tools/lint_mcp.py
   ```

9. **Write `mcphub.json`.** Use the raw GitHub URL of `openapi.json` and a token
   value that contains an obvious `YOUR_...` placeholder.
10. **Write `source.md`.** Include the original URL, how it was found, every
    change made, the terms checked, the test status, and the last checked date.
11. **Open a pull request.** CI validates every spec, lints it, checks the
    read-only variant is current, and checks the MCPHub placeholder.

## Checklist

- [ ] The source URL and access date are in `source.md`.
- [ ] The vendor's redistribution terms were checked and recorded.
- [ ] `openapi-spec-validator` accepts `openapi.json` and `openapi.readonly.json`.
- [ ] `python tools/lint_mcp.py` reports no errors.
- [ ] `python tools/make_readonly.py --check` passes.
- [ ] `servers` is a real production URL; no localhost.
- [ ] At least one security scheme exists and the top-level `security` uses it.
- [ ] Every operation has a unique operationId of at most 40 characters, matching
      `[a-z0-9_]`.
- [ ] No parameter or request-body property name falls outside
      `^[a-zA-Z0-9_.-]{1,64}$`.
- [ ] No bracketed names such as `q[field]` remain.
- [ ] No real token, account ID, customer domain or email address is committed.
- [ ] `mcphub.json` points at the raw `openapi.json` URL and uses a placeholder.
- [ ] `source.md` records the MCPHub test result, including any unconfirmed auth
      or untested feature such as deepObject.
- [ ] The converter is re-runnable against an updated vendor document.

## Licensing and safety rules

- Label every spec **unofficial** and link its source.
- Do not add an API whose terms forbid redistributing its documentation. Note the
  terms checked in `source.md`.
- Never commit real tokens, account IDs, customer domains or emails. Use
  placeholders such as `<your-token>`, `YOUR_API_TOKEN` or `example.com`.
- The MIT licence covers this repository's code, tooling and documentation. Spec
  content is a derivative of each vendor's documentation and remains subject to
  that vendor's terms.
