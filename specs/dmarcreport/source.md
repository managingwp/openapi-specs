## Authentication

DMARC Report uses an `Authorization` header with a token prefix:

```
Authorization: Token token=<your-token>
```

Create a token in `app.dmarcreport.com` under profile icon > API Tokens > New Api
Token. The spec declares a `TokenAuth` apiKey scheme in the `Authorization`
header. The source document had no security definitions and included a real
token-shaped example in its auth prose; that example was removed.

`mcphub.json` uses MCPHub's `apiKey` security type with the placeholder value
`Token token=YOUR_DMARC_REPORT_API_TOKEN`.

## Changes from the source document

1. **Swagger 2.0 to OpenAPI 3.0.3.** Parameters gained `schema` wrappers, array
   parameters kept their `items`, and Swagger-only fields were dropped.
2. **Server override.** The source had `host: localhost:3000` and a `basePath`
   that was itself the full URL `https://api.dmarcreport.com`. The output sets
   `servers` to `https://api.dmarcreport.com`; localhost is never published.
3. **Authentication added.** A `TokenAuth` apiKey scheme in the `Authorization`
   header, with top-level `security`. The source declared no scheme.
4. **operationIds rewritten.** All 50 operations use the Gist's short snake_case
   mapping, e.g. `get_v2_accounts_account_id_domains_domain_id_agg_reports.json`
   became `list_aggregate_reports`. Names are unique, at most 40 characters and
   contain only `[a-z0-9_]`.
5. **Bracketed query parameters collapsed.** The source used `q[field]` query
   parameters, which Claude rejects as tool input names. Each operation now has a
   single `q` object parameter with `style: deepObject` and `explode: true`; the
   wire format stays `q[field]=value`. This covers the nine affected operations:
   `list_aggregate_reports`, `search_aggregate_report_records`,
   `get_aggregate_report_stats`, `get_top_email_sources`,
   `get_alignment_failures`, `get_compliance_trends`, `list_failure_reports`,
   `list_mta_sts_reports`, and `list_mta_sts_failure_details`.
6. **Form fields nested into JSON bodies.** `formData` parameters such as
   `domain[mta_sts_policy][mx_age]` became nested object properties in an
   `application/json` request body. The source advertised
   `application/x-www-form-urlencoded` and `multipart/form-data`; JSON is used
   because that is what MCP bridges send. Array fields remain arrays.
7. **Types corrected.**
   - Path IDs described as `number` are `integer`.
   - Paging and count parameters (`page`, `per`, `limit`, `days`, `count_eq`) are
     `integer`.
   - `true`/`false` string enums are `boolean` (for example `active`,
     `spf_alignment_eq`, `dkim_alignment_eq`, `publish`, and the hosted-service
     toggles).
   - The integer enum on `dmarc_compliance_eq` is `integer`, not `string`.
   - `pct` is `integer`.
8. **Descriptions cleaned.** HTML became Markdown, bullet lists that had been
   flattened into one paragraph were split back into list items, duplicated
   wording ("search by search by") and "in_days" were fixed, and the example
   token in the auth instructions was replaced with `<your-token>`.
9. **Responses completed.** The source defined only error responses. Every
   operation gained a generic JSON `200`; `components.responses.Error` is shared
   by all 4xx/5xx responses. The PDF report endpoint returns
   `application/pdf` with a binary string schema.
10. **Read-only variant generated.** `openapi.readonly.json` keeps the 34 read
    operations and drops the 16 write operations. It is generated by
    `tools/make_readonly.py`.
11. **Secret check.** The converter refuses to write output containing
    token-shaped values, and the linter scans every published spec again.

## Test status

- **OpenAPI validation:** `openapi-spec-validator` accepts `openapi.json` and
  `openapi.readonly.json`.
- **MCP lint:** `tools/lint_mcp.py` reports 50 operations (34 read, 16 write)
  with no errors.
- **MCPHub:** the spec loads in MCPHub and the operation list is generated.
- **Authentication:** the first test call returned `401 Unauthorized`.
  Authentication is **not confirmed** yet; the token value or header format may
  still need adjustment.
- **deepObject:** **untested.** Filtering through the `q` object depends on the
  MCP bridge understanding OpenAPI `deepObject` serialization. MCPHub's support
  has not been verified. If your bridge does not support it, call the API
  directly for filtered queries or add a flat, bridge-specific variant.
- **Live coverage:** no broader live testing has been done. Treat write
  operations as untested against a real account.

## Reproducing

```sh
python tools/convert_dmarcreport.py --source /path/to/2.0.json
python tools/make_readonly.py
python tools/lint_mcp.py
```
